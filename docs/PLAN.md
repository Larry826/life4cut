# Life4Cut implementation plan

## 목표 사용자 흐름

1. 시작 화면
2. 촬영 안내 확인
3. 카메라 권한 요청
4. 카메라 미리보기
5. 3초 카운트다운
6. 첫 번째 사진 촬영
7. 같은 방식으로 총 네 장 촬영
8. 촬영 결과 미리보기
9. 전체 재촬영 또는 개별 사진 재촬영
10. 프레임 디자인 선택
11. 완성 이미지 미리보기
12. PNG 파일로 저장
13. 처음부터 다시 촬영

## 기본 화면 상태

복잡한 라우터를 사용하지 않고 초기 버전에서는 `App` 컴포넌트의 화면 상태로 관리한다.

- `start`: 서비스 이름, 간단한 설명, 촬영 시작 버튼을 보여주는 첫 화면이다.
- `guide`: 촬영 방식, 카메라 권한, 이미지가 브라우저 안에서만 처리된다는 안내를 보여준다.
- `camera`: 카메라 권한 요청 후 실시간 미리보기와 촬영 진행 상태를 보여준다.
- `countdown`: 사진 촬영 직전 3초 카운트다운을 크게 보여준다.
- `review`: 촬영한 네 장의 썸네일을 확인하고 전체 또는 개별 재촬영을 선택한다.
- `frame`: 프레임 색상, 날짜 표시, 하단 문구를 고르는 꾸미기 화면이다.
- `result`: 최종 네컷 이미지를 미리보고 PNG로 저장하거나 처음부터 다시 촬영한다.

## 단계별 구현 계획

### Phase 1: 기본 UI 틀

- [ ] Vite 기본 예제 화면 제거
- [ ] 앱 전체 레이아웃 제작
- [ ] 시작 화면 제작
- [ ] 서비스 이름, 설명, 촬영 시작 버튼 배치
- [ ] 보라색, 검정색, 분홍색 디자인 시스템 구성
- [ ] 모바일과 데스크톱 반응형 처리

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`
- `src/index.css`

확인 방법:
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.
- 모바일 폭과 데스크톱 폭에서 시작 화면의 버튼과 텍스트가 겹치지 않는지 확인한다.

### Phase 2: 촬영 안내와 카메라 연결

- [ ] 촬영 전 개인정보 안내 작성
- [ ] 카메라 권한 요청 흐름 구현
- [ ] `navigator.mediaDevices.getUserMedia` 사용
- [ ] `video` 미리보기 연결
- [ ] 전면·후면 카메라 선택 가능 여부 검토
- [ ] 모바일 전면 카메라 좌우 반전 처리
- [ ] 권한 거부 및 장치 없음 오류 처리
- [ ] 화면 이동 시 MediaStream 정리

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`

확인 방법:
- HTTPS 또는 localhost 환경에서 카메라 권한 요청이 표시되는지 확인한다.
- 권한 거부 시 한국어 오류 안내가 보이는지 확인한다.
- 화면을 벗어날 때 카메라 표시등이 꺼지는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 3: 네 장 연속 촬영

- [ ] 3초 카운트다운 구현
- [ ] 촬영 횟수 표시
- [ ] `canvas`를 이용한 `video` 프레임 캡처
- [ ] 네 장의 이미지를 React 상태로 보관
- [ ] 촬영 사이 잠깐의 준비 시간 제공
- [ ] 촬영 완료 후 `review` 화면으로 이동
- [ ] 카메라 비율과 결과 이미지 비율 일치

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`

확인 방법:
- 네 장이 순서대로 촬영되는지 확인한다.
- 캡처 이미지가 찌그러지거나 뒤집히지 않는지 확인한다.
- 네 번째 촬영 후 자동으로 결과 확인 화면으로 이동하는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 4: 촬영 결과 확인 및 재촬영

- [ ] 네 장 썸네일 표시
- [ ] 선택한 사진 한 장만 재촬영
- [ ] 전체 재촬영
- [ ] 다음 단계 이동
- [ ] 이미지 순서가 바뀌지 않도록 처리

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`

확인 방법:
- 개별 재촬영 후 해당 위치의 사진만 바뀌는지 확인한다.
- 전체 재촬영 시 기존 네 장이 초기화되는지 확인한다.
- 다음 단계 이동 시 사진 순서가 유지되는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 5: 프레임 꾸미기

- [ ] 세로 네컷 프레임 미리보기 제작
- [ ] 검정, 흰색, 보라색, 분홍색 프레임 제공
- [ ] 날짜 표시 여부 선택
- [ ] 하단 문구 입력
- [ ] 프레임 선택 결과 실시간 반영
- [ ] 입력 글자 수 제한

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`

확인 방법:
- 프레임 선택이 즉시 미리보기에 반영되는지 확인한다.
- 긴 문구를 입력해도 화면이 깨지지 않는지 확인한다.
- 날짜 표시 토글이 정상 동작하는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 6: 최종 이미지 합성과 저장

- [ ] `canvas`에 사진 네 장 배치
- [ ] 선택한 프레임과 문구 반영
- [ ] 고해상도 최종 이미지 생성
- [ ] PNG 다운로드
- [ ] 모바일 브라우저 저장 동작 확인
- [ ] Object URL과 메모리 정리

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`

확인 방법:
- 저장된 PNG에 네 장의 사진, 프레임, 문구가 모두 포함되는지 확인한다.
- 모바일 브라우저에서 다운로드 또는 공유 동작이 가능한지 확인한다.
- 반복 저장 후 메모리 누수나 console 오류가 없는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 7: 품질 개선

- [ ] 모바일 세로 화면 점검
- [ ] 화면 회전 대응
- [ ] 키보드 접근성
- [ ] 버튼 focus 표시
- [ ] 로딩 상태
- [ ] 중복 클릭 방지
- [ ] 카메라 오류 화면
- [ ] 새로고침 시 데이터 초기화 안내
- [ ] 브라우저 console 오류 확인

수정 예상 파일:
- `src/App.jsx`
- `src/App.css`
- `src/index.css`

확인 방법:
- 모바일, 태블릿, 데스크톱 폭에서 주요 흐름을 확인한다.
- 키보드만으로 주요 버튼에 접근할 수 있는지 확인한다.
- 중복 클릭과 권한 오류 상황에서 화면이 멈추지 않는지 확인한다.
- `npm.cmd run build`로 빌드 성공 여부를 확인한다.

### Phase 8: Netlify 배포

- [ ] `npm.cmd run build` 확인
- [ ] GitHub `main` 브랜치 push
- [ ] Netlify에 GitHub 저장소 연결
- [ ] Build command 설정
- [ ] Publish directory 설정
- [ ] 배포된 HTTPS 주소에서 카메라 확인
- [ ] 모바일 실제 기기 테스트

Netlify 설정 예상값:

- Build command: `npm run build`
- Publish directory: `dist`

수정 예상 파일:
- 배포 설정이 필요한 경우 Netlify 웹 설정을 먼저 사용한다.
- 저장소에 설정 파일이 필요할 때만 별도 문서를 확인하고 추가한다.

확인 방법:
- Netlify 배포 로그에서 빌드 성공 여부를 확인한다.
- 배포된 HTTPS 주소에서 카메라 권한 요청과 미리보기가 작동하는지 확인한다.
- 실제 모바일 기기에서 촬영과 PNG 저장을 확인한다.

## 완료 기준

- [ ] 카메라 권한을 요청할 수 있다.
- [ ] 사진 네 장을 순서대로 촬영할 수 있다.
- [ ] 전체 또는 개별 재촬영이 가능하다.
- [ ] 프레임을 선택할 수 있다.
- [ ] 최종 네컷 이미지를 PNG로 저장할 수 있다.
- [ ] 촬영 이미지가 외부 서버로 전송되지 않는다.
- [ ] 모바일과 데스크톱에서 사용할 수 있다.
- [ ] `npm.cmd run build`가 성공한다.
- [ ] Netlify HTTPS 주소에서 카메라가 작동한다.
